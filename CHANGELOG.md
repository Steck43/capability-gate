## [Unreleased]

### Added
- Leak scan for private names and personal paths before they merge. `.gitleaks.toml` extends the default gitleaks rules with Windows and POSIX user-home paths and private IPv4 ranges. `scripts/leak_denylist_scan.py` checks the same shapes plus a list of names that lives outside the tree (the `LEAK_DENYLIST` repo secret, or an untracked local file under `.git/info`), so the list itself is never published. A name matches as a case-insensitive substring, so a name glued to other text still hits; an entry can be a regex instead. Pre-commit checks the lines a staged change adds. CI runs the scanner from the default branch rather than from the change, checks each commit in the range on its own plus its message, and checks the pull request title and body; on a push to main the range starts at the previous tip. CI fails closed when the list is not set or the range is empty. File names that git quotes are unquoted, and a diff header the scanner cannot parse fails the run. The current tree still has known hits, so CI does not yet scan the full tree. Known gaps: non-UTF-8 text, binary files, file names themselves, `~` and environment-variable home paths, forward-slash Windows paths, other IP address forms, and commits made with `--no-verify` until CI sees them. `tests/test_leak_scan.py`.
- Hook behavior tests (`tests/test_hook_behavior.py`) run the Claude Code hook script through its `main()` and the Hermes plugin through `register()` and the `pre_tool_call` it registers. Each must deny an off-grant read, allow an in-grant read, and deny when `Gate.evaluate` raises. These are the wiring control.
- Wiring source check (`tests/test_live_wiring.py`, `tests/wiring_manifest.json`), a fast hint beside the behavior tests. It requires `main()` to reach `_pre`, `register()` to bind `pre_tool_call`, and each hook to assign `gate.evaluate` on its straight-line path to a name a later `if` reads as `.verdict`. Calls after an unconditional return, raise, or process exit, and calls under a constant guard, do not count. It cannot see a rebound gate or an error handler that allows; the behavior tests catch those. The descriptor-bound read is a pending entry held as a strict expected failure (`raises=AssertionError`), and the read binding cannot be dropped from the manifest without moving into the wired entries.
- Known-answer test linter (`scripts/kat_lint.py`, pre-commit and CI). KAT files are found among test files: those anywhere under tests/ and at the top level whose names start with test in any case, plus every file pytest itself collects (testpaths, python_files and norecursedirs from pytest.ini, or pytest's defaults). Among them, case-insensitively: names like test_k*.py or containing kat, a # KAT comment, or a test that names a receipts/ path. tests/test_kat_lint.py and tests/test_public_text_paths.py are exempt unless they carry a # KAT comment. Files named on the command line are linted whatever their name. Fiat outcomes are rejected anywhere in a KAT file, in tests, helpers, nested functions and at module level: a fail, exit or dynamic-code call (`pytest.fail`, `pytest.exit`, `sys.exit`, `os._exit`, `os.abort`, `os.kill`, `signal.raise_signal`, `exit`, `quit`, `eval`, `exec`, `compile`, `runpy`) under any spelling the lint can resolve: import and assignment aliases, `_pytest.outcomes`, `__import__` and `importlib.import_module` with a constant or folded name, `getattr` with a constant or folded name, `vars(m)[...]`, `m.__dict__[...]`, `globals()[...]`, `builtins` and `__builtins__`, and literal list or tuple elements, referenced or called (so passing one to `functools.partial` counts); `getattr` or an import with a name it cannot fold on pytest, sys, os, builtins, importlib, runpy, unittest or signal; raising `AssertionError`, `SystemExit`, `KeyboardInterrupt`, a pytest outcome exception or `unittest.SkipTest`; an `assert` that folds to a constant or always raises; inside a function or class, an `if` or `while` test, statement, return value or assigned value that always raises; and in a test, a `raise` that runs on every path and nothing catches. Constant folding covers literals and empty literals, names assigned exactly once (module, function, tuple unpacking, annotated, walrus, chained), ternaries, `and` and `or` with a constant side, `not`, arithmetic, comparisons and chains, membership in an empty container, subscripts and slices, and pure builtins (`bool`, `int`, `len` and the rest); a second binding of any kind, or a mutable literal passed anywhere it could change, stops folding. Skip and xfail forms: in a KAT file, any reference to `pytest.mark.skip` (decorator, class mark, `pytestmark`, `pytest.param(marks=...)`, `add_marker`, alias, `getattr`, `with_args`, wrapper) or the `unittest` skip and expected-failure decorators, any imperative skip, xfail, importorskip or `skipTest` not under an `if` that is purely a platform check, and a `skipif` whose condition is neither purely a platform check nor constant false. In every test file: `skipif` with no condition or a condition that folds true (string conditions are parsed), a condition that mixes a platform check with anything else or names a platform value that does not exist, a condition taken from a function parameter, `xfail(strict=...)` that is not provably true, `xfail(run=False)`, `**` arguments to `skipif` or `xfail`, imperative `pytest.xfail`, and in a test function a forced exit or dynamic code. Each KAT must reach the real gate on its straight-line path before any return or raise: `.evaluate` or `.throw` on a `capability_gate.Gate` built in the test or returned by a same-file fixture or helper; `open_authorized_read`, `_pre`, `main` or `pre_tool_call` imported from `capability_gate` or `adapters`; or a subprocess running `adapters/claude_code_hook.py`. A gate from a test helper module, conftest, a local or subclassed class, `getattr`, `type()` or `importlib` does not count, nor does a gate module beside the test file, a gate the test's world patches (`setattr`, `monkeypatch`, `mock.patch` or attribute assignment on a gate, the Gate class or a gate function, in the test, its fixtures, autouse fixtures, helpers or the module), or a call in dead code (constant-false branch, empty loop or comprehension, unconsumed generator, `while` body) or inside `pytest.raises`, `contextlib.suppress` or `assertRaises`. Each KAT must then assert on the gate's result, directly, through a name, a flag or counter set under a branch, `match` or handler that depends on it, a list it was appended to, a same-file fixture that returns it, or a same-file helper that asserts on it. Known gaps: one file at a time, so a gate patched or a fixture supplied from conftest or another module, a module loaded by file path, and environment-dependent conditions outside skip marks are not judged; fault injection into anything other than a gate object, the Gate class and the gate functions is allowed on purpose. `tests/test_kat_lint.py`.

### Fixed

- The KAT lint ends a test's straight path at a call to `pytest.xfail`, `skip`, `fail` or `exit`, so an answer assert after one never satisfies the KAT, and its folder walk passes `followlinks=False` explicitly (it already did not follow links, and the floor guard refuses any link).
- The KAT lint follows the gate's class through an unpacking (`k, = (type(gate),)`), a loop over a fixed display of it, a same-file helper that returns `type(x)` or `x.__class__` of the gate, and `__bases__[i]` as well as `__mro__[i]`, so patching any of these is a gate patch. A name inside an unpacking target is now read as its paired value everywhere in the lint instead of also as an unknown store.
- The KAT lint counts an `except ... as d`, an `import ... as d` or `from ... import ... as d`, a store through `globals()` (a key it cannot fold takes every name out), and a `global` or `nonlocal` declaration as rebinding the result name, beside the assignments, unpackings, loop targets and `with` names it already counted. A `raise` that a `try` catches no longer ends the straight path.
- The KAT lint accepts one form of assert on the gate's answer instead of refusing listed shapes: a single `==` or `is` between a verdict (read from a gate result, or a name that only ever holds one) and a `Verdict` member or verdict string, or between a gate call's own answer (or its `returncode`) and a literal. A KAT needs one such assert on its own straight path; a helper's assert, a `!=` or `is not`, a branch, a loop's `else` and a `while` body do not count. Every other assert that reads the answer is refused, apart from three named richer forms (a reason substring, the enforced flag, a paths literal) that never satisfy a KAT alone; boolean combinations, displays, comprehensions, calls, formatting, helpers, partials, properties, subscripts, membership, chained comparisons, ternaries and walrus forms are all refused however spelled. `tests/test_kill_switch.py` changes two asserts to the accepted form (a comprehension over two denies becomes two verdict asserts; a reason `or` becomes the phrase the gate writes).
- The KAT lint reads every write into a mapping one way: a subscript store or delete, `|=`, a write method (`update`, `setdefault`, `pop`, `popitem`, `clear`, `__setitem__`, `__delitem__`, `__ior__`), `operator.setitem`, `delitem` and `ior`, `dict`'s methods called unbound, and `monkeypatch.setitem` or `delitem`. A write into a module namespace (`globals()`, `locals()`, `vars()`, `vars()` or `__dict__` of a module object, a function's `__globals__`, or any name ever bound to one) under `Verdict`'s, the gate class's or a gate module's own name, or under a key the lint cannot fold, means that name is not the real one; a write into the gate's, the gate class's or a gate module's `__dict__` or `vars()`, or a name bound to one, patches the gate. The protected names now include the names the file imports `capability_gate` and `adapters` under, so `sys.modules[__name__].capability_gate = ...` means the gate class read through it is not the real one. This restores the `vars()` of a module object, `|=` and aliased forms the previous narrowing had let through.
- The KAT lint reads a function's `__globals__` as its module's namespace, so a store, `update` or alias through it under `Verdict` or the gate class's name makes either not real, and a store on the object a namespace holds under one of those names (`globals()['Gate'].evaluate = ...`, `f.__globals__['Gate'].evaluate = ...`) counts the same. The gate class is read only directly: the name it is imported as, `type(gate)`, `gate.__class__`, its `mro()` or `__mro__` entries, or a name bound only to one, may be read as an attribute, called, passed to `isinstance` or `issubclass`, compared with `is` or `==`, used as an annotation, or bound to a tracked alias. Passed on as a value (a call argument, a container element, a return or yield value, a lambda body), it can be patched where the lint does not follow it, and is refused; an unapplied fixture that passes it to `monkeypatch.setattr`, accepted before, is refused too. Known gap: the lint is static, and these are the paths into the module namespace it reads; any other dynamic path (a frame's `f_globals`, a `gc` or `inspect` walk, code built at run time) is out of its scope.
- The KAT lint reads `Verdict` rebound through an object as not real: any store to an attribute named `Verdict` (`sys.modules[__name__].Verdict`, a name bound to this module), `setattr` with the key `Verdict`, or with a key it cannot fold on a module reached through `sys.modules`, `importlib.import_module` or `__import__`, a store under that key in a `__dict__`, `vars()`, `globals()` or `locals()` (directly or through a name bound to one), and `update`, `setdefault` or `|=` on any of those mappings (another object's `__dict__` is that object's own and is read by the result and patch rules). The gate class is judged the same way under every name the file imports it as, so `sys.modules[__name__].Gate = ...` and its `setattr`, `__dict__` and alias forms mean the class is not the real one. A name a function binds only to the gate's class (`type(gate)`, `gate.__class__`, `Gate`, `mro()`, through a walrus too) is read as the gate class by that function's own bindings, whatever the same name means elsewhere in the file, so a store through it patches the gate. In a `try` whose handler may finish without raising again, the straight path enters the body's first statement only when it is a simple one, and an assert there with a message that is not a constant does not count, since a failing assert evaluates its message. A `finally` that may return, or break or continue out of the `try`'s own loop, takes the body off the straight path. With no handler that can swallow, the `try`'s `else` is on the straight path. The refusal messages name the accepted form, `<result>.verdict is Verdict.X`.
- The KAT lint judges the gate fixture a test takes, the gate class and `Verdict` by the same binding walk as a result name, so a `match` or `except` capture, a walrus anywhere (a call argument included), a `for` or `with` target, an import, and a `global`, `nonlocal` or nested-function `nonlocal` store of any of them is a rebinding; the previous entry's claims that nothing rebinds `Verdict` and that the walrus was covered held for result names only. A verdict counts only when compared by identity: one `is` between the result's verdict and a `Verdict` member. `==`, against a member or a verdict string, reads through `__eq__`, which `type(d.verdict)`, `d.verdict.__class__`, `mro()`, `setattr`, `monkeypatch` or an alias of the class can override, so it is refused; a member of the real Enum cannot be reassigned. A gate call's own answer compared with a literal keeps `==`. In a `try` whose handler may finish without raising again, only the body's first statement is on the straight path, since any later statement may follow a caught raise. Three shapes earlier rounds accepted are now refused: a verdict compared with `==` to a member or a string.
- The KAT lint holds the answer to the gate call's own return. A helper's or fixture's result counts only when every return or yield is the gate call, a name that only ever holds a gate result, or another such helper; one that only reaches the gate and returns something else does not. A name stops holding a result under the binding forms read before this round (a match capture, a nested `def` or `class`, a `nonlocal` store in a nested function, a walrus) and under any store into it (an attribute, `setattr` or `object.__setattr__`, its `__dict__` or `vars()`). A statement that may return, or end the test in an imperative skip or xfail, ends the straight path, so an accepted assert after a conditional `return` or a handler that leaves no longer counts; a skip under a test of the platform alone stays with the platform rules. A `Verdict` token counts only when it resolves to the real `capability_gate.Verdict` and nothing in the file stores into `globals()` under that name or changes `sys.modules`. Patching any attribute of the `capability_gate` module (`_decide`, `_path_allowed`) is a gate patch, and the class reached through `.mro()` is read like `__mro__`. A test decorated by anything but a pytest mark, a module-level store to a defined name, and a bare xfail mark with no reason or strict are refused. Three shapes earlier rounds accepted are now refused: a return under an unknown branch before the assert (two cases), and patching a non-gate attribute of the gate's module (two cases). Known gaps: a `with` whose exit may swallow the assert's failure (a custom context manager, `ExitStack` with `suppress`), writes through `sys._getframe().f_locals` (Python 3.13 only), N7 to N9, N12 to N14 and H5d to H5n as already named, and the `--require-kats` CI wiring (with the leak scan pull request).
- The KAT lint is frozen at the shapes it refuses on this branch; no new shape is added to it. Whether a KAT's answer follows the gate moves to a behavioral check that runs each KAT under swapped gates and decision mutants (`scripts/kat_swap.py`, its own pull request). Known gaps this lint leaves to that check, named in its docstring: a gate fixture the test never receives, a patch applied from another file, the gate class or a module namespace reached by a route the lint does not read, and a test that changes the gate module on disk.
- Known gaps of the KAT lint, now in its docstring: the floor's KAT lint job does not pass `--require-kats` yet (wiring it into floor.yml is #84's change); truthy-by-construction tests are caught only in the listed shapes, and a display with a starred part of unknown contents is left alone because it may be empty; a helper folds only when its one return reads none of its parameters or returns one unchanged.
- The KAT lint follows the gate's class through an alias (`k = gate.__class__; setattr(k, ...)`, `k = type(gate); k.evaluate = ...`, `type(gate).__mro__[0]`), counts any store that rebinds a result name (`d, = (fake,)`, `[d] = [fake]`, `for d in [fake]`), and accepts every alias of UTF-8 in a coding cookie (`utf8`, `U8`, `UTF8`). The duplicated header-fix bullet below is removed.
- The KAT lint treats the `else` of a `while` loop whose test is always true (`while True:`, `while 1:`) as dead: that `else` runs only when the test turns false, so an assert there never runs and does not count as asserting on the gate's answer.
- The KAT lint folds a constant routed through a call it can read: `(lambda: False)()` and `functools.partial(bool, 0)()` where they are written, an identity helper (`def ident(x): return x`) or any same-file helper whose one return reads none of its parameters, and a method of a sealed same-file class called on a fresh instance (`Fixed().value()`). So `assert ident(False)` beside a real assert fails by fiat, and `assert ident(True) or d.reason` is a tautology.
- The KAT lint sees an expression compared with itself in disguise: a walrus is both its target and its value (`(y := d) is y`), a one-off display picked by a constant index is its element (`[d][0] is d`), `x in (x,)` and `x in [x]` always hold, and `len()` of a display whose shape fixes its size (`len({id(d)}) == 1`, `len({1: d}) == 1`) is a constant comparison. A starred part keeps a display's length unknown.
- The KAT lint rejects an assert whose test is truthy by construction: a display that is provably non-empty (a plain element, or a starred non-empty display such as `(*[d],)`; a starred part with unknown contents may be empty, so `[*d.reason]` still tests the answer), a generator, an f-string or a lambda; `repr`, `str`, `format` or `hasattr` of anything; `any` over a display with an element that folds true; and `len(x) >= 0`, `0 <= len(x)` or `len(x) > -1`.
