## [Unreleased]

### Added
- Leak scan for private names and personal paths before they merge. `.gitleaks.toml` extends the default gitleaks rules with Windows and POSIX user-home paths and private IPv4 ranges. `scripts/leak_denylist_scan.py` checks the same shapes plus a list of names that lives outside the tree (the `LEAK_DENYLIST` repo secret, or an untracked local file under `.git/info`), so the list itself is never published. A name matches as a case-insensitive substring, so a name glued to other text still hits; an entry can be a regex instead. Pre-commit checks the lines a staged change adds. CI runs the scanner from the default branch rather than from the change, checks each commit in the range on its own plus its message, and checks the pull request title and body; on a push to main the range starts at the previous tip. CI fails closed when the list is not set or the range is empty. File names that git quotes are unquoted, and a diff header the scanner cannot parse fails the run. The current tree still has known hits, so CI does not yet scan the full tree. Known gaps: non-UTF-8 text, binary files, file names themselves, `~` and environment-variable home paths, forward-slash Windows paths, other IP address forms, and commits made with `--no-verify` until CI sees them. `tests/test_leak_scan.py`.
- Hook behavior tests (`tests/test_hook_behavior.py`) run the Claude Code hook script through its `main()` and the Hermes plugin through `register()` and the `pre_tool_call` it registers. Each must deny an off-grant read, allow an in-grant read, and deny when `Gate.evaluate` raises. These are the wiring control.
- Wiring source check (`tests/test_live_wiring.py`, `tests/wiring_manifest.json`), a fast hint beside the behavior tests. It requires `main()` to reach `_pre`, `register()` to bind `pre_tool_call`, and each hook to assign `gate.evaluate` on its straight-line path to a name a later `if` reads as `.verdict`. Calls after an unconditional return, raise, or process exit, and calls under a constant guard, do not count. It cannot see a rebound gate or an error handler that allows; the behavior tests catch those. The descriptor-bound read is a pending entry held as a strict expected failure (`raises=AssertionError`), and the read binding cannot be dropped from the manifest without moving into the wired entries.
- Known-answer test linter (`scripts/kat_lint.py`, pre-commit and CI). KAT files are found recursively and case-insensitively: names like `test_k*.py` or containing `kat`, a `# KAT` comment, or a test that names a `receipts/` path. In those files it rejects any `pytest.fail` (under any import alias) and any `raise AssertionError`, and requires each test to reach the gate on its straight-line path, directly or through a same-file helper or fixture, before any return or raise. Constant-guarded and unreachable calls do not count. The receiver of the call is not type-checked, and imperative `pytest.skip` or `pytest.xfail` are not yet rejected. `tests/test_kat_lint.py`.
- `pytest.ini` sets `xfail_strict = true`, so an expected failure that starts passing fails the run instead of hiding a fix or a broken test, and turns `SyntaxWarning` into an error. No existing expected failure passes under the strict setting.
- Floor config test (`tests/test_floor_config.py`). It fails when `xfail_strict` or the `SyntaxWarning` error filter is turned off, when a guardrail CI job or step (gitleaks, the name and path scan with its title and body step, the KAT linter, the tests) is removed from `floor.yml`, when the scan stops reading the denylist secret, or when the local leak and KAT hooks or the custom gitleaks rules are removed. Turning a guardrail off now needs this file changed in the same review.
- The floor reruns when a pull request title or body is edited (`pull_request` types include `edited`), so the title and body leak scan reads the current text, not the text at the last push. `tests/test_floor_config.py` pins the trigger list.
- Floor guard (`scripts/floor_guard.py`, `.github/floor-pins.json`). Every job in `floor.yml` and the workflow's top-level settings are pinned by sha256 of their parsed form, so run text, shell, inputs, working directory, timeouts, runner, matrix, `if` and permissions all count; so are the guard files: the floor guard and its tests, `kat_lint.py`, the leak scanner, the craft scripts, every workflow file, the pytest configuration, every `conftest.py`, and the new hash-locked `requirements-ci.lock`. A changed, added or removed job or guard file fails. Rules also judge the pinned values: every run block is parsed as shell (bashlex) and every command in it is checked, so nothing can switch off stop-on-error (`set +e`, `+o errexit`, `shopt`, or any shell value other than the allowlisted pipefail values), hide a failing command (the full list is in the stop-on-error entry under Fixed), write a runner environment, path, output or state file by any spelling or through a non-literal redirect, run a constructed, indirect or unlisted command, use git subcommands that change the tree, write guard files, install anything but the lock file, override the package index, or make lint non-failing. Check names are compared after matrix expansion and case folding across every workflow. Checkout inputs may not change ref, repository or file set; siblings check out at a fixed commit. A new `floor (guard from base)` job loads the guard, its pins and the lock from the base branch and fails closed when the base has none. The leak job no longer falls back to the change's own scanner. Guardrail jobs install only `requirements-ci.lock` with `--require-hashes`. The craft jobs no longer switch off stop-on-error, and the empty-diff job takes its base from the environment instead of interpolating it into the script, with no fallback to the root commit. `tests/test_floor_config.py` plants 57 tampers in the real workflow; each fails against the committed pins, and every one a rule can judge still fails with the pins regenerated.
- OS-1/OS-2 collected as strict xfail under `tests/test_os_01_02_collected.py` (Track B). Design under `design/os/` stays unscanned. Receipt `OS-1-2-COLLECTED-XFAIL-2026-10-11.md`. No implementation. No paper claim.

- Explicit deny for path segments `.env` and `.aegis` even when a grant glob covers the parent directory (independent review of #60). Deny-by-default alone is not enough once those names sit inside a granted tree; the reason names the protected segment. The check follows `realpath` (symlink aliases under a whole-home grant) and the realpath of the parent for new files; also denies `.env.*`, `.envrc`, and case-folded `.ENV` / `.Aegis` (independent review of #65 asked for a fix first). Names that merely *end* in `.env` (for example `foo.env`) stay allowed - only the exact segment `.env` / `.env.*` / `.envrc` / `.aegis` is protected.
- Full-suite runner (`scripts/run_full_suite.py`) that sets `AEGIS_ATOMS_ROOT` and `ISOLATION_LAYER_ROOT` to detached worktrees at the sibling pins in `tests/test_gate_boundary.py`, so a local pytest matches CI instead of the operator's live sibling HEAD.
- Folded Part C design scaffolds under `design/part-c/`, plus pre-code OS, specification-gaming, and policy-decay designs. None of those folders change the gate decision path.
- Wave 3 measured-gap receipt: AgentDojo, GAIA2, TAU-Bench, and SWE-Gym stays unmeasured until a live boxed run exists; B7, live AgentDojo, and paid runs remain held. The Wave 3 document is a MEASURED-GAP design, not a paper claim.

Live Hermes, AgentDojo, box, and judge claims remain explicitly unmeasured.
- The Hermes hook exports its live allow `Decision` and `tool_call_id` through the shared per-call context, so downstream atoms can bind their receipt and box prove to the exact gate decision that was evaluated.
- Plugin bundle version `0.1.1` (tag `plugin-v0.1.1`): same SLSA attestation path as `plugin-v0.1.0`, zip includes `__init__.py` plus the kill switch tip. Verify: `gh attestation verify capability-gate-plugin-0.1.1.zip --repo Steck43/capability-gate`.
- Kill switch. `Gate.throw` creates a marker beside the decision log (the log path plus `.halt`) and appends one THROWN row to the hash chain; a second throw adds no row. `Gate.evaluate` materializes paths once, then reads the marker before the allowlist, so a running gate denies the next call with no restart, and a marker it cannot read is a deny. A call that names the marker is denied with the switch on or off. Only a human removing the marker clears it. Observe mode still blocks nothing (`test_kill_switch_blocks_in_observe`, strict expected failure). `tests/test_kill_switch.py` is gate-level only: it does not show the live hook calls the gate.
- Claude Code adapter (`adapters/claude_code_hook.py`), Windows. The decider runs as a `PreToolUse` hook. Allow is exit 0 with no output, so Claude Code's own permissions still apply; every deny and every error is exit 2 with a reason, under a 5 s self-deadline. Calls carry no skill label and are judged as `UNLABELED`, which the allowlist must grant by name. A `PostToolUse` twin flags a call whose input changed after the check. `tests/test_cc_adapter.py` pins each branch.

### Fixed

- Every per-line lint exemption is held by inventory. The guard counts each `noqa` comment ruff would honour (with codes separated by commas, spaces or both, blanket, or after other comment text) per file and code, and any new one, one more of an existing code, or a blanket one is a violation, so silencing ruff on a line needs a change to the guard. Notebooks are read too: a code cell's file-level or per-line exemption counts like a Python file's, and a notebook that does not parse is a violation.
- A test module skipped as a whole is not a run. The conftest records whole-module skips separately and the modules where at least one test reached its call, and `scripts/run_record_check.py` fails the tests job on any module skipped whole, or whose tests were all skipped before their call (a module-level skip mark, or a skip on every test), except the one listed module that needs a Hermes install the job leaves out. An expected failure counts as a run. A record with no tests collected fails, and that branch is now tested.
- `tests/test_leak_scan.py` uses a fake private name other than the shared list's canary, which the scanner now skips (#97); with the canary as the fake name, 8 of its cases failed.
- Disclosed residuals: a test module runs arbitrary code inside pytest, so it can rewrite results (for example by patching pytest's reporting objects) without registering a plugin, and it can write a plausible run record and then end the process. `test_a_forged_record_then_an_exit_fails_the_check` pins the second as a strict expected failure, so a fix that closes it will turn the suite red until the mark is removed.
- The floor guard reads every command as written. Each word keeps its quotes and backslashes when it is compared with a job's exact command shapes and required commands, so a word the shell would not expand (`'$RUNNER_TEMP/x'`, `\$RUNNER_TEMP/x`) never matches a shape that expects the variable, and an assignment-only command is judged like any other. A `$` inside single quotes, after a backslash or opening `$'...'` quoting is a violation in any step, and so is any tracked or untracked path that holds `$`, a backtick or a backslash (read from the git index, so a name the platform cannot create still counts). Together these stop a committed file from standing in for the base guard, the leak scanner or the authorship check, with the pins regenerated or not. Required actions are matched against each step's `uses` value and required commands against parsed commands only, so a comment or a string never satisfies either.
- The lint configuration is pinned and judged exactly. `ruff.toml` must parse to the guard's copy of it, so an added ignore, exclude, include or extend, a `select`, or `ALL` or `*` anywhere is a violation; any other `ruff.toml`, any `.ruff.toml` or `.ignore`, a pyproject `[tool.ruff]` table in any spelling or folder, a file-level `# ruff: noqa` or `# flake8: noqa`, and a tracked file that git ignores (ruff skips those) are violations too.
- A plugin a test module declares in any form fails the run. The floor's root `conftest.py`, pinned by exact content in the guard, refuses any plugin that registers once collection starts, which is when pytest loads a module's `pytest_plugins`, however the name was built (a sum of strings, a join, a reversed string, a module `__getattr__`, `exec`). The guard also flags a summed string and a module `__getattr__` statically.
- A run that ends early never passes the tests job. pytest exits 0 when a test module calls `os._exit(0)` during import or during a test, so the conftest writes a run record only from a finished session (`FLOOR_RUN_RECORD`), and `scripts/run_record_check.py` fails the job unless the record exists, the exit status is 0, every collected test reported, and every test module under the root ran or was skipped as a whole.
- `scripts/leak_denylist_scan.py` tags a matching path with an HMAC under a fresh random key each run instead of a fixed sha256 prefix, so a list of candidate names cannot confirm a tag offline.
- Known limits: a test module still runs arbitrary code inside pytest, so one that forges the run record before it ends the process, or removes the conftest's hooks before they fire, is not caught. Until this guard is on the base branch, the floor-guard job runs the base's older guard, which does not have these rules.
- Guardrail python runs isolated. Every `python` call in `floor.yml` is `python -I`, so neither a script's folder nor the working directory is importable and no `PYTHON*` variable or user site applies: a stdlib-named module beside a script (`scripts/argparse.py`) or a package's `__main__` in the checkout (`pip/__main__.py`) cannot run in place of the guard, the scanner, pip or a craft script. The guard rejects any python call without `-I`, and tests run the live kat-lint and install commands beside planted shadows.
- Every floor command is judged as a parsed command with an exact shape. Each job has a table of the simple commands it may run (words, then redirects, as the shell parser reads them); anything else fails, so git takes no upload-pack, output, external diff, textconv, no-index, refspec, URL or file remote, tar runs only in the actionlint job with its pinned arguments, and no cp, mkdir or redirect can create a file pytest would load. Function definitions, loops, subshells and command groups are refused; `echo`, `printf`, `true`, `:`, `test` and `[` may not name a guarded tool; and each job's required commands must run as parsed commands, so an echoed copy of the text no longer counts.
- Workflow-level `defaults` hold only `run.shell`; a working directory or any other default there is a violation, as at job and step level.
- The guard loads every workflow strictly: a repeated key, a `!!binary`, set or date value, or any other tag is one "does not load" violation and exit 1, never a traceback.
- A test module that names `pytest_plugins` (assigned, annotated, as an attribute or as a string) is a violation. `sitecustomize.py`, `usercustomize.py`, `*.pth` and `.pytest.ini` are violations wherever they sit, and a pytest section in `pyproject.toml`, `setup.cfg` or `tox.ini` is caught in any spacing or quoting; a `pyproject.toml` that does not parse fails.
- `scripts/leak_denylist_scan.py` scans file names in every mode and never prints a path that matches a rule: such a path shows as `file #` and a hash. A git failure prints only the subcommand and exit code, and an unreadable file only a hash. In files mode the name is judged relative to the working directory.
- Known gaps: the floor-guard job definition comes from the pull request (only the guard script, pins and lock come from the base, and for a stacked pull request that base is another feature branch); a repository ruleset or required workflow is the structural fix and is a maintainer settings action. Test modules run arbitrary code inside pytest in the tests job, so a module can still reach pytest by means other than `pytest_plugins`; the floor guard and its tests are pinned against the base for that reason. The secrets (names and personal paths) and floor (guard from base) jobs fail closed until main carries the scanner and the guard.
- The floor guard's rules now judge, with the pins regenerated in the same change, every class a legitimate floor change could otherwise slip past:
  - the pin file loads strictly: a parse failure (including deep nesting), a repeated key at any level, an escaped key or name, or any bytes other than what `--update-pins` writes is one malformed violation with no traceback, and the in-tree pin file must exist and load even when the guard judges with pins from the base;
  - a protected-jobs table pins each floor job's key, the check names it produces and text its steps must contain, so a renamed job, a decoy that takes a check name, or a protected key reused for a trivial step is caught, and a job missing from the table is a violation;
  - jobs keep only allowlisted conditions and no `needs`, run on `ubuntu-latest` with a 1 to 30 minute timeout and a matrix that expands to at least one run; step conditions and step environment (exact values) are allowlisted;
  - the floor workflow's triggers are exactly its pinned triggers, no workflow file may use a privileged trigger, and a workflow with any write permission may run only on push, dispatch, schedule or branch protection events;
  - pytest takes only `-q`; every allowlisted script and `ruff` runs with its exact allowlisted arguments; the floor's top-level keys and concurrency are fixed, and every job's timeout is exactly 10 minutes, so no value is left to the pins alone;
  - python runs only the allowlisted guard scripts, `-m pytest` or `-m pip`; only `git show` may write into the temp directory; the script variables in the craft jobs may name only their listed scripts;
  - every lock entry is a version-pinned, hash-locked requirement; pytest config is only `pytest.ini` with its three allowed keys, strict xfail and SyntaxWarning as an error, a norecursedirs that cannot hide `tests`, and no `conftest.py` or pytest section elsewhere;
  - root and nested `sitecustomize.py`, `usercustomize.py` and `*.pth` files are pinned guard files.
- A guardrail step fails whenever its command fails. The floor sets `bash --noprofile --norc -eo pipefail {0}` as the default shell, and every run step must run under that value or `bash -eo pipefail {0}`; a step with no explicit pipefail shell is a violation. A `shell` value at step, job-defaults or workflow-defaults level passes only when it is exactly one of those two values: flags are not parsed, so an option after the placeholder, a parse-only or command-string option, an end-of-options marker, an extra file, another shell, `bash -e {0}`, `sh -e {0}` or a non-string value is a violation. Run text may not use an `if`, `while` or `until` condition, `&&`, `||`, a background `&`, command or process substitution, or `!`. Each allowlisted value is run with real bash on a failing script and on a failing pipe, and the step fails. The floor's own steps were rewritten to plain commands: bases come from exact `${{ }}` expressions in the step environment, the craft scripts are called by fixed path, and the authorship check is `scripts/no_ai_trailers.py` on a history file.
- The floor guard fails on any symlink it could be asked to judge: every tracked link (index mode 120000) and every untracked, unignored link in a checkout, or any link on disk outside the skipped directories elsewhere, so a link cannot hide or redirect a file pytest collects.
- The floor guard skips only directories that pytest also skips (`.git/`, `.venv/`, `.tmp/`), so the pinned sibling checkouts that `scripts/run_full_suite.py` places under `.tmp/` no longer read as added guard files. `node_modules/` is no longer skipped, because pytest recurses into it here.
- `.gitleaksignore` ignores exactly one gitleaks finding by fingerprint: the `generic-api-key` match on `.github/floor-pins.json` line 31 in commit 14b3be1, where a pin digest sat under the job key `secrets`. The tree no longer has that shape, and history is fixed forward, not rewritten. `.gitleaks.toml` has no allowlist, and `.gitleaksignore` is a pinned guard file.

A job named `secrets` beside a 64-hex value had read as a credential to the secret scanner. The floor guard parses the file strictly: an unknown or missing key, a non-list group, an empty or duplicate name, or a digest that is not 64 lowercase hex fails the floor as malformed instead of defaulting.
- `REPRODUCE-PAPER.md` and `receipts/K2-ADAPTER-S3-2026-10-09.md` no longer name a private repository; the live replay receipt is described as private. Earlier commits still hold the name; history is not rewritten.

The README no longer says the audit trail is real from the first call or that a fresh clone's `pytest -q` passes; it says what the log does and how the suite is run against its pinned siblings. The workflow comment no longer cites a stale test count.

The same `LEAK_DENYLIST` value feeds isolation-layer's public surface scan, which needs that fixed canary; here it would have flagged every test fixture that uses the fake term. A relative path with no usable base folder is denied.
